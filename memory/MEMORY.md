# Berit Team Memory Index

> Index only. Each entry points to a typed memory file. Keep under 200 lines.

## Team

- [Team context](team_context.md) — agents, roles, working norms, ownership map.

## Project

- [Project context](project_context.md) — active projects, goals, deadlines.
- [Decisions](decisions.md) — dated architectural / product decisions with rationale.

## Workflow

- [Open questions](open_questions.md) — unresolved items + owner + status.
- [Waiting on team](waiting_on_team.md) — items blocked on a human teammate.
- [Feedback](feedback.md) — validated approaches and corrections.

## How to use

1. Read `MEMORY.md` at session start (`/berit-start` does this automatically).
2. Treat each linked file as a hint, not truth — verify with git/files before acting.
3. Update via `/berit-end` at session end. Do not silently overwrite memory mid-session.
4. See [../docs/file-routing.md](../docs/file-routing.md) for what belongs where.
