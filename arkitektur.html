Claude Cowork Plugin — v0.3.0

berit-team

Multiagent-plugin som simulerar ett svenskt produktteam. En orchestrator (Berit) delegerar uppgifter till nio specialistagenter via Claude Agent SDK:ns subagent-system.

01 — Filstruktur

Plugin-katalog

Plugin:et lever som en remote plugin under .remote-plugins/. All konfiguration sker genom fyra typer av filer: plugin-manifest, agent-definitioner, skill-definition och command-definitions.

berit-team/ ├── .claude-plugin/ │ └── plugin.json # manifest: namn, version, beskrivning ├── agents/ # anna.md..torsten.md — frontmatter (name, description, tools, model) + system prompt ├── skills/ │ ├── berit-orchestrator/ │ │ └── SKILL.md # orchestrator-instruktioner, workflow, handoff-protokoll │ ├── requirements-review/ # task-verb: kravgranskning │ ├── test-scenario-generation/ # task-verb: testscenarier från krav │ ├── meeting-summary/ # task-verb: möteslogg → beslut + actions │ ├── risk-review/ # task-verb: risk-genomgång │ └── regression-test/ # task-verb: kör kanoniska prompts före version-bump ├── commands/ │ ├── berit.md # /berit — entrypoint, startar orchestratorn │ ├── berit-start.md # /berit-start — läs minne, briefing (read-only) │ ├── berit-end.md # /berit-end — recap, befordrar beslut till minne │ ├── anna.md # /anna — business analyst (sonnet) │ ├── gunnar.md # /gunnar — produkt & spec (opus) │ ├── astrid.md # /astrid — UX & design (opus) │ ├── maja.md # /maja — data & analytics (sonnet) │ ├── pelle.md # /pelle — frontend (opus) │ ├── sigrid.md # /sigrid — backend (opus) │ ├── torsten.md # /torsten — infra & DB (opus) │ ├── ingrid.md # /ingrid — QA (read-only) (opus) │ └── erik.md # /erik — dokumentation (sonnet) ├── docs/ # constitution, decision-authority, file-routing, regression-tests ├── memory/ # persistent minne mellan sessioner — MEMORY.md + typade filer ├── outputs/ # daterade leveranser: outputs/YYYY-MM-DD/ ├── scripts/ │ └── sync-agents.mjs # genererar src/agents/*.ts från agents/*.md (npm run sync:agents) ├── src/agents/ # genererade SDK-agentmoduler — rör aldrig för hand └── README.md
02 — Plugin manifest

plugin.json

Minimalt manifest. Inga MCP-servrar eller externa beroenden — plugin:et använder enbart Agent-verktyget för att starta subagenter.

{
  "name": "berit-team",
  "version": "0.3.0",
  "description": "Swedish product team orchestrated by Berit...",
  "author": { "name": "Jonathan Svedelius" },
  "keywords": ["orchestrator", "multi-agent", "product-team", "swedish"]
}
03 — Två anropslägen

Orchestrerat vs. direkt

Plugin:et exponerar två sätt att nå teamet. /berit startar den fulla orkestreringsloopen. De individuella kommandona (/anna, /gunnar, etc.) kör en enskild agent direkt, utan orchestrator.

/berit <uppdrag>

Laddar berit-orchestrator-skillen. Skapar handoff.md och delegerar till rätt agenter i sekvens via subagent_type — harnessen laddar varje agents persona, verktyg och modell. Model: opus.

/agent <uppgift>

Laddar agentens system prompt. Läser handoff.md om den finns. Kör uppgiften isolerat. Model varierar: opus eller sonnet.

07 — Handoff-protokoll

.context/handoff.md

Kontinuiteten mellan agenter sker via en delad fil: .context/handoff.md. Berit skapar filen innan första delegering och är dess enda skribent. Specialisterna läser den men skriver aldrig i den — de rapporterar leveranser och beslut i sitt slutmeddelande, och Berit för in dem. Det eliminerar skrivkrockar mellan parallella agenter.

.context/handoff.md — exakt format
# Projektkontext

## Uppdrag
[Vad och varför — satt av Berit vid projektstart]

## Beslut
- [Datum] [Agent]: [Beslut och motivering]
- [Datum] [Agent]: [Beslut och motivering]

## Leveranser
- [Agent] → [fil]: [beskrivning]
- [Agent] → [fil]: [beskrivning]

## Kontrakt & Scheman
[Delade typer, DB-scheman, API-kontrakt.
 Skrivs in av Berit innan parallella agenter startar,
 så att Sigrid och Pelle bygger mot samma spec.]

## Öppna frågor
- [Fråga] (flaggad av [Agent])
- [Fråga] (flaggad av [Agent])

Steg 1: Berit skapar

Innan första delegering fyller Berit i Uppdrag, mål och constraints.

Steg 2: Agenter läser + rapporterar

Varje agent läser filen innan start. Rapporterar beslut och leveranser i sitt slutmeddelande — skriver aldrig själv i filen.

Steg 3: Berit för in + verifierar

Efter varje agent för Berit in leveranserna och besluten i filen och kontrollerar att inget krockar med tidigare steg.

09 — Delegering

Hur Berit anropar en agent

Berit använder Agent-verktyget med subagent_type: "berit-team:<namn>" — harnessen applicerar agentens persona, verktygsrestriktioner och modell från agents/*.md. Delegeringsmeddelandet innehåller bara handoff-instruktion, specifik uppgift, relevanta filer och beroenden — aldrig inklistrade system prompts.

Delegerings-template
// 1. Välj agent — harnessen laddar persona,
//    verktyg och modell från agents/sigrid.md
subagent_type: "berit-team:sigrid"

// 2. Handoff-instruktion
"Read .context/handoff.md first."

// 3. Specifik uppgift
"Sigrid, your task: Implementera auth-endpoint
 baserat på Gunnars spec i .context/handoff.md"

// 4. Kontext
"Relevant files: src/api/auth.ts
 Dependencies: Torstens schema (se handoff.md)
 Constraints: RLS måste vara aktivt"

// 5. Efteråt: Sigrid rapporterar leveranser i sitt
//    slutmeddelande — Berit för in dem i handoff.md
10 — Command-frontmatter

Hur commands konfigureras

commands/ingrid.md (exempel)
---
description: Ingrid granskar kod, säkerhet och kvalitet
allowed-tools: Read, Bash, Glob, Grep         # ingen Write/Edit
model: opus
argument-hint: <uppgift>
---

Read `${CLAUDE_PLUGIN_ROOT}/agents/ingrid.md` and load
Ingrid's system prompt (the body below the frontmatter).

You are now Ingrid. The user's task is: $ARGUMENTS

IMPORTANT: You have no Write or Edit tools.
You review and report only.

allowed-tools

Styr agentens verktygsaccess. Berit har Agent, Ingrid saknar Write/Edit, analytiker saknar Bash/Edit.

model

Satt per command-fil. Anna, Maja och Erik kör sonnet. Resten kör opus.

$ARGUMENTS

Användarens input injiceras direkt via variabeln. Agenten får uppgiften utan omtolkning.

11 — Quality gate

Kvalitetskontroll

Konfliktlösning

Om en agents output krockar med ett tidigare beslut i handoff.md — Berit stoppar och löser innan nästa steg.

Kritiska issues

Om Ingrid flaggar kritiskt — Berit delegerar fix till rätt specialist, sedan re-review av Ingrid.

Slutrapport

Berit levererar: vad som byggdes, designval, kända begränsningar. På svenska.

12 — Operativ modell (v0.3.0)

Konstitution, beslut, minne

v0.3.0 lyfter teamet från en ren delegeringsloop till ett operativt lager som överlever mellan sessioner. Fyra docs/-filer kodifierar regler och beslutsrätt, memory/ håller kontext över tid, och två kommandon ramar in varje session.

Konstitution

docs/constitution.md samlar hårda regler: vad Berit får och inte får, hur specialister levererar, när handoff är obligatorisk. En sida — läses först vid varje session.

Beslutsbefogenheter

docs/decision-authority.md definierar fyra tiers per agent: vad de får besluta själva, vad som kräver godkännande, vad som måste eskaleras till människa. Godkännandeformat är standardiserat.

Filplacering

docs/file-routing.md ger en regelkarta: minne i memory/, arbets-kontext i .context/handoff.md, leveranser i outputs/YYYY-MM-DD/. Ingen tvekan om var något hör hemma.

Regressionstester

docs/regression-tests.md listar kanoniska prompts som måste passera innan version bumps. Skill regression-test kör dem.

Tre lager av minne

Minnestopologi
memory/                          # persistent, mellan sessioner
├── MEMORY.md                    # index — pekare till typade filer
├── team_context.md              # roller, normer, ägarskap
├── project_context.md           # aktiva projekt, mål, deadlines
├── decisions.md                 # daterade beslut + rationale
├── open_questions.md            # olösta items + ägare
├── waiting_on_team.md           # blockerat på en människa
└── feedback.md                  # validerade angreppssätt + korrigeringar

.context/handoff.md              # working memory för ett uppdrag
outputs/2026-05-20/              # daterade leveranser (specs, reviews, recaps)

Sessionsritualer

/berit-start

Read-only briefing från memory/. Listar öppna frågor, väntar-på-team och senaste beslut innan något nytt körs. Skriver aldrig till minnet.

/berit-end

Recap + minnesbefordran. Sessionsbeslut, nya öppna frågor och feedback skrivs till rätt typad fil i memory/. Skriver aldrig tyst mitt i en session.

Task-verb-skills

Fem komponerbara skills som vilken specialist som helst kan anropa — separerade från agentidentitet. Berit väljer rätt verb för rätt specialist.

SkillVad den görTypiska anropare
requirements-reviewGranskar krav: täckning, testbarhet, oklara beroendenAnna, Gunnar, Ingrid
test-scenario-generationHärleder testscenarier (positiva, negativa, edge) från kravIngrid, Pelle, Sigrid
meeting-summaryMöteslogg → strukturerad beslutslista + action itemsBerit, Erik, Gunnar
risk-reviewRisk-genomgång: säkerhet, drift, leverans, beroendenIngrid, Sigrid, Torsten
regression-testKör kanoniska prompts från docs/regression-tests.md före version bumpBerit, Ingrid

Varför: Tidigare kunde Berit inte komma ihåg ett beslut från igår eller om en intressent fortfarande väntade. Nu finns kontexten kvar — och task-verben gör att kompetens kan flyttas mellan agenter utan att duplicera prompts.
