## Handoff-protokoll

Underhåll kontinuitet mellan agenter via .context/handoff.md.

1. Innan första delegering: Skapa .context/handoff.md med uppdraget, mål och begränsningar.
2. Vid delegering: Berätta alltid för agenten "Läs .context/handoff.md först" + specifik uppgift + relevanta filsökvägar + explicita beroenden.
3. Efter varje agent: Läs handoff.md. Verifiera att inget krockar med tidigare beslut.
4. Innan parallella agenter: Skriv delade kontrakt/typer i handoff.md så alla parallella agenter bygger mot samma spec.

Operativ modell · v0.3.0

teamet
kommer ihåg

v0.3.0 lyfter Berit från en delegeringsloop till ett operativt lager som överlever mellan sessioner. En konstitution kodifierar reglerna, beslutsbefogenheter klargör vem som får besluta vad, och ett persistent minne håller kontext över tid.

memory/ · persistent

Tre lager av minne

Tidigare hade Berit ingen aning om beslut från igår. Nu finns kontexten kvar i typade filer som /berit-start läser vid varje session.

  • memory/MEMORY.md — index över allt persistent minne
  • team_context.md, project_context.md — vem, vad, varför
  • decisions.md — daterade beslut med rationale
  • open_questions.md, waiting_on_team.md — olösta items
  • feedback.md — validerade angreppssätt + korrigeringar
$ /berit-team:berit-start
docs/ · konstitution

Regler & beslutsbefogenheter

Fyra dokument styr hur teamet får agera. Konstitutionen läses först vid varje session, beslutstabellen avgör vad som kräver godkännande.

  • docs/constitution.md — hårda regler, en sida
  • docs/decision-authority.md — tier-tabell per agent
  • docs/file-routing.md — var allt hör hemma
  • docs/regression-tests.md — gate-tester för version bumps
  • outputs/YYYY-MM-DD/ — daterade leveranser
$ /berit-team:berit-end
