Architecture

skills vs
real agents

Berit-team can be used in two ways — depending on whether you work interactively in Claude Code or want to run the team automated in a pipeline.

Skills / Claude Code

Conversation-based agents

Skills are markdown files loaded into your active conversation. The slash command /berit-team:berit activates Berit's persona and instructions directly in the session — no separate processes.

  • Runs in the same Claude Code session you're working in
  • Shares conversation history and context
  • No API key or extra installation required
  • Best for interactive, iterative work
  • Agents spawn as isolated subprocesses via the Agent tool
$ /berit-team:berit Build an invoice module
Agent SDK · TypeScript

Process-isolated agents

The SDK app runs Berit as a standalone Node.js process via @anthropic-ai/claude-agent-sdk. Each subagent is fully isolated — its own tools, model and permissions.

  • Runs outside Claude Code — perfect for CI/CD and pipelines
  • Programmatic control via TypeScript
  • Inherits your existing claude binary's auth
  • Best for automation and scheduled jobs
  • Cost visible: $0.70–2.00 per complete assignment
$ npm start -- "Review the auth flow"

## Handoff Protocol

Maintain continuity between agents via .context/handoff.md.

1. Before first delegation: Create .context/handoff.md with the assignment, goals and constraints.
2. When delegating: Always tell the agent "Read .context/handoff.md first" + specific task + relevant file paths + explicit dependencies.
3. After each agent: Read handoff.md. Verify nothing conflicts with previous decisions.
4. Before parallel agents: Write shared contracts/types in handoff.md so all parallel agents build against the same spec.

## Default Flow

Anna (requirements) → Gunnar (spec) → Astrid (UX review)
  → Maja (measurement plan) → Torsten (schema)
  → Sigrid + Pelle (parallel, against shared contracts)
  → Ingrid (QA) → Erik (documentation)
  → Berit (final report + any rework)

Adapt the order to the task. Not every task requires all agents.

## Quality Gate

- If an agent's output conflicts with a previous decision → stop and resolve the conflict before continuing.
- If Ingrid finds critical issues → delegate the fix to the right specialist, then have Ingrid review again.
- Final report includes: what was built, key design decisions, known limitations.
